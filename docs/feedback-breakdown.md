# 本轮反馈拆解

## 0. 范围说明

这份文档只拆解本轮需求，不代表马上实现。

用户明确提出的方向：

1. 做成类似 IDE / 剪映的项目制工具。
2. 打开软件后先进入项目首页，不是每次都重新导入视频。
3. 新建项目时由用户选择项目保存文件夹。
4. 导入视频时，把视频复制进项目目录。
5. 首页需要最近项目。
6. 第一版加入数据库，因为后续数据会复杂。
7. UI 参考剪映，首页和编辑界面都采用深色主题。
8. 视频播放时是否自动播放口述脚本，不作为强制逻辑，只做成一个可开关的选项。

本轮先不写“视频播放与口述脚本同步”作为独立需求。

未明确提出的内容暂不做，例如账号系统、云同步、会员、素材市场、模板、团队协作、平台发布。

## 1. 需求一：项目制 / Workspace

### 用户问题

现在每次打开软件都要重新选择视频、重新分析，不符合实际使用方式。

用户希望它像写 Java 的 IDE 或剪映一样，有项目概念。

### 我的理解

当前“一次性导入视频”的模式，需要改成“项目制”。

一个项目应该保存：

- 项目名称。
- 项目保存位置。
- 项目文件。
- 已导入的视频文件。
- 视频元数据。
- 分析结果。
- 全局理解结果。
- 分段结果。
- 口述脚本。
- 每条脚本的时间点、文本、状态。
- 用户修改过的内容。
- 后续生成的 TTS 音频。
- 导出记录。

### 新建项目流程

新建项目时，打开系统文件夹选择器，让用户自己选择或创建项目文件夹。

这点参考 IDE 的项目创建方式：用户决定项目目录，软件不替用户强行生成固定目录。

建议流程：

```text
点击新建项目
→ 打开 Finder 文件夹选择器
→ 用户选择或新建一个空文件夹
→ 软件在该文件夹中初始化项目
→ 进入编辑界面
→ 导入视频
→ 视频复制进项目目录
```

第一版不处理文件夹冲突细节：

- 默认用户选择的文件夹可用。
- 如果文件夹不是空的，先不做特殊处理。
- 如果文件夹里已有 `yuying.project.json`，先不做覆盖/冲突判断。

### 导入视频规则

导入视频不是只保存原路径，而是把视频复制进项目目录。

原因：

- 原视频被移动或删除后，项目仍然可用。
- 项目可以整体迁移。
- 后续缓存、脚本、音频、导出文件都在同一个项目目录里。

### 建议项目目录结构

```text
用户选择的项目文件夹/
  yuying.project.json
  yuying.db
  source/
    input.mp4
  cache/
    segments/
    context/
    tts/
  exports/
```

项目文件保存核心状态：

```json
{
  "name": "项目名称",
  "sourceVideoPath": "source/input.mp4",
  "duration": "03:20",
  "resolution": "1920x1080",
  "globalContext": "...",
  "scripts": []
}
```

数据库保存结构化数据：

- 项目信息。
- 视频素材。
- 分析任务。
- 全局理解。
- 视频片段。
- 口述脚本。
- TTS 音频。
- 导出记录。

### 最近项目

需要最近项目列表。

首页显示最近打开或编辑过的项目：

- 项目名。
- 项目路径。
- 上次编辑时间。
- 视频文件名。

点击最近项目后直接打开编辑界面。

最近项目显示所有记录，不设固定数量上限。

### 是否需要数据库

已确认：第一版加入数据库。

原因：

```text
后续数据会复杂
需要保存项目、视频、片段、脚本、音频、导出等结构化数据
```

建议使用 SQLite。

建议结构：

```text
每个项目一个 yuying.db
全局再有一个 app.db 保存最近项目
```

项目内数据库：

```text
project-folder/
  yuying.project.json
  yuying.db
```

`yuying.project.json` 只保存项目入口信息和版本信息。

`yuying.db` 保存主要业务数据。

## 2. 需求二：口述自动播放开关

### 用户修正

不要求视频播放和口述脚本强制同步。

可以做成一个开关，放在合理位置。

### 我的理解

这个功能不是本轮核心需求，不作为独立“播放同步”需求展开。

只在 UI 上预留一个可选开关：

```text
自动播放口述
```

建议位置：

- 编辑界面播放器附近。
- 或底部时间轴右上角工具区。
- 或口述脚本面板顶部。

开关关闭时：

```text
视频播放只播放原视频声音
用户可以手动试听单条口述
```

开关打开时：

```text
视频播放到某条脚本时间点附近时
尝试播放对应口述
```

第一版可以先只做开关 UI，不实现复杂同步逻辑。

## 3. 需求三：UI 重构

### 用户问题

当前 UI 太丑，需要重构。

用户给了两个参考：

1. 剪映初始界面。
2. 剪映剪辑界面。

### 已确认方向

UI 采用深色主题。

首页和编辑界面都做深色，参考剪映风格。

### 首页结构

参考剪映首页，但只保留我们需要的功能。

建议结构：

```text
左侧导航
  首页
  最近项目

主区域
  新建项目
  打开项目
  最近项目列表
```

不做：

- 登录账号。
- SVIP。
- 云空间。
- 模板推荐。
- 营销活动。
- AI 图片设计等无关入口。

### 编辑界面结构

参考剪映剪辑界面，但适配口述影像。

建议布局：

```text
顶部栏
  项目名
  保存状态
  分析
  生成旁白
  导出

左侧面板
  导入的视频素材
  口述脚本列表
  分析结果

中间
  视频播放器

右侧
  当前脚本参数
  文本编辑
  时间点
  状态

底部
  时间轴
  原视频轨道
  口述脚本轨道
```

### 时间轴

底部时间轴第一版只写基础展示，不写脚本块拖动能力。

应该显示：

- 原视频轨道。
- 口述脚本轨道。
- 每条描述作为片段块。
- 当前播放头。
- 当前脚本高亮。

暂不写：

- 拖动脚本块。
- 多轨剪辑。
- 精细剪辑工具。

## 4. 建议实现顺序

### 阶段一：项目首页和项目制

目标：

- 打开软件先看到深色项目首页。
- 可以新建项目。
- 新建项目时打开 Finder，让用户选择或创建项目文件夹。
- 可以打开已有项目。
- 首页显示最近项目。
- 最近项目显示所有记录。
- 初始化项目数据库。

验收：

- 关闭软件后重新打开，能从最近项目继续。

### 阶段二：导入视频复制进项目

目标：

- 在项目中导入视频。
- 视频复制到项目目录的 `source/` 下。
- 项目数据库记录相对路径。

验收：

- 原始视频移动位置后，项目仍然能打开并预览项目内的视频。

### 阶段三：保存和恢复分析结果

目标：

- 分析结果写入项目数据库。
- 用户修改脚本文本后自动保存。
- 重新打开项目后，脚本仍然存在。

验收：

- 不需要重新导入视频。
- 不需要重新分析。

### 阶段四：深色编辑界面重构

目标：

- 编辑界面改成剪映式深色布局。
- 左侧素材/脚本区。
- 中间播放器。
- 右侧参数区。
- 底部基础时间轴。

验收：

- 视频、脚本、参数、时间轴位置清晰。
- UI 不再像普通表单页。

### 阶段五：口述自动播放开关

目标：

- 在合理位置加“自动播放口述”开关。
- 初版可以先影响预览行为，不做复杂同步。

验收：

- 开关关闭时，不自动读口述。
- 开关打开时，允许后续接入按时间点播放口述。

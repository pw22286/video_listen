# UI 生成提示词：口述影像生成工具 MVP

你是一个资深产品设计师和前端工程师。请为一个 Electron 桌面端应用生成第一版 UI。这个应用用于帮助视频创作者为本地视频生成“口述影像版”视频。

## 产品目标

第一版只验证核心能力：

1. 导入本地视频。
2. 自动分析视频画面和音频空隙。
3. 生成口述影像脚本初稿。
4. 用户编辑脚本、试听旁白。
5. 导出带口述旁白的 MP4。

不要做模型管理、模型下载、服务商配置、账号系统、云同步、团队协作、素材库、模板市场、平台发布。

AI API、TTS API、模型名称、Base URL、API Key 都先由代码写死，不需要出现在 UI 里。

## 目标用户

面向视频创作者、课程制作人员、公益/政府/企业内容团队。用户不一定懂音视频后期，所以 UI 要清晰、直接、工作流导向。

界面风格应该像一个专业的桌面创作工具，而不是营销网站。不要做 landing page，不要做大 hero，不要做宣传文案页。

## 首屏布局

应用打开后直接进入工作台。

如果还没有导入视频，显示一个简洁的空状态：

- 中央拖拽区域：拖入视频文件
- 主按钮：选择视频
- 支持格式提示：MP4、MOV、M4V
- 最近项目列表可以先不做

导入视频后进入主工作台。

## 主工作台结构

使用三栏或上下结合布局，适合 1440x900 桌面窗口。

推荐布局：

```text
顶部工具栏
左侧：视频预览 + 分析状态
中间：时间轴 / 脚本列表
右侧：当前描述编辑面板
底部：任务进度 / 导出状态
```

### 顶部工具栏

包含：

- 项目名称
- 导入视频按钮
- 分析按钮
- 生成旁白按钮
- 导出按钮
- 当前状态：未分析 / 分析中 / 待编辑 / 可导出 / 导出中 / 已完成

按钮状态要合理：

- 未导入视频时，只能点击“导入视频”。
- 导入视频后，可以点击“开始分析”。
- 分析完成后，可以编辑脚本和生成旁白。
- 旁白生成后，可以导出。

### 左侧视频预览区

包含：

- 视频播放器。
- 播放/暂停。
- 当前时间 / 总时长。
- 音量按钮。
- 当前帧截图预览。
- 当前片段状态，例如“检测到 3.2 秒可插入口述的空隙”。

不要做复杂剪辑功能，不要做多轨视频编辑。

### 中间脚本时间轴

这是核心区域。

每一条口述脚本作为一个条目展示：

- 时间码，例如 `00:01:23.500`
- 预计时长，例如 `3.4s`
- 描述文本
- 状态：待生成 / 已生成 / 有冲突 / 已禁用
- 小按钮：试听、重生成、删除、启用/禁用

条目应该按时间顺序排列。点击条目后，视频跳到对应时间，右侧显示详细编辑。

需要有明显的冲突状态：

- 如果旁白时间过长，标记“超出空隙”。
- 如果离对白太近，标记“可能遮挡对白”。

### 右侧编辑面板

显示当前选中的脚本条目：

- 起始时间输入。
- 文本编辑框。
- 预计朗读时长。
- 对应画面缩略图。
- 试听按钮。
- 重生成按钮。
- 删除按钮。
- 启用/禁用开关。

文本编辑框要足够大，因为用户会大量改文案。

### 底部任务区

显示当前后台任务：

- 抽帧中
- 检测静音区间
- 生成画面描述
- 生成口述脚本
- 生成 TTS
- 混音导出

展示进度条、当前步骤、失败信息。失败时提供“重试”按钮。

## 必须设计的页面/状态

请至少生成以下 UI 状态：

1. 空项目状态：等待导入视频。
2. 视频已导入、未分析。
3. 分析中：显示步骤进度。
4. 分析完成：出现脚本列表。
5. 选中脚本条目：右侧可编辑。
6. 有冲突条目：用明显但克制的提示。
7. 生成旁白中。
8. 导出完成：显示导出路径和打开文件夹按钮。
9. 错误状态：API 调用失败或 FFmpeg 处理失败。

## 视觉风格

要求：

- 专业、克制、清晰。
- 像生产力工具，不像营销页面。
- 使用浅色主题优先。
- 信息密度适中，方便长时间编辑。
- 不要使用大面积紫色、蓝紫渐变、玻璃拟态、装饰性光斑。
- 不要使用卡片套卡片。
- 不要用 hero 区块。
- 圆角控制在 8px 以内。
- 图标按钮请使用 lucide 图标。

建议颜色：

- 背景：接近白色或浅灰。
- 主色：深青色、绿色或中性蓝均可，但不要满屏同色。
- 警告：琥珀色。
- 错误：红色。
- 成功：绿色。
- 文本：高对比深灰。

## 交互原则

- 用户应该始终知道下一步该点什么。
- 长任务必须有进度。
- AI 生成内容必须可编辑。
- 失败必须可重试。
- 不要隐藏关键状态。
- 不要用浮夸动效。
- 不要让用户配置模型。

## 文案要求

使用中文界面。

按钮示例：

- 导入视频
- 开始分析
- 生成旁白
- 导出视频
- 试听
- 重生成
- 删除
- 打开导出文件夹
- 重试

状态文案示例：

- 等待导入视频
- 正在分析视频
- 正在生成口述脚本
- 发现可能遮挡对白的描述
- 旁白已生成
- 导出完成
- 处理失败，请查看错误详情

不要在界面里写长篇产品介绍。

## 技术约束

如果生成前端代码：

- 使用 React + TypeScript。
- 使用 Electron 桌面应用思路设计，不要做移动端优先。
- 可使用 Tailwind CSS。
- 可使用 lucide-react。
- 所有数据先 mock。
- 不需要真实调用 API。
- 不需要真实处理视频。
- 但组件结构要方便后续接入真实后端。

推荐组件：

- `AppShell`
- `TopToolbar`
- `VideoPanel`
- `ScriptTimeline`
- `ScriptItem`
- `ScriptEditor`
- `TaskProgress`
- `EmptyProject`
- `ExportComplete`
- `ErrorBanner`

## 输出要求

请输出一个可运行的前端界面原型，优先完成主工作台。

重点不是视觉炫技，而是让用户一眼看懂：

1. 当前视频是什么。
2. 当前处理到哪一步。
3. 哪些口述脚本需要编辑。
4. 如何试听和修改。
5. 如何导出成片。

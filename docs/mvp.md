# 口述影像生成工具 MVP 文档

## 1. 产品定位

面向视频创作者的桌面端工具。创作者在发布视频前，将本地视频导入软件，自动生成口述影像脚本，经过人工审核和编辑后，导出带口述旁白的视频或独立音轨。

第一版不做实时辅助观看工具，也不尝试给 YouTube、B 站等平台上的已有视频直接插入音轨。

## 2. MVP 目标

让创作者完成一条 3-10 分钟视频的基础口述影像制作流程：

1. 导入本地视频。
2. 自动分析视频中的对白、静音空隙、画面变化和屏幕文字。
3. 生成带时间码的口述影像脚本初稿。
4. 在时间轴上编辑脚本、试听旁白。
5. 导出带口述旁白的混音视频。

成功标准：

- 创作者无需懂音视频后期，也能完成一次可试听、可导出的视频处理。
- 生成结果允许人工修改，不承诺完全自动达到专业口述影像成片质量。
- 软件默认只要求用户安装本 App；FFmpeg 随 App 内置。

## 3. 非目标

MVP 暂不做以下内容：

- 平台视频下载或解析，例如 YouTube、B 站链接下载。
- 实时识别正在播放的视频画面。
- 手机 App。
- 完整本地大模型推理运行时。
- 模型下载中心。
- 团队协作、云项目同步、多人审稿。
- 多语言批量翻译。
- 专业影视交付格式全覆盖。
- 视障用户端播放器。

这些能力可以作为后续版本规划。

## 4. 目标用户

第一批用户应聚焦在有明确无障碍发布需求的内容生产者：

- 教育课程创作者。
- 政府、公益机构视频团队。
- 企业培训内容团队。
- 知识类、教程类视频创作者。
- 小型纪录片或宣传片制作团队。

不建议第一版面向重度影视制作团队，因为他们对口述质量、混音、审片和交付格式要求更高。

## 5. 核心用户流程

### 5.1 首次设置

用户打开软件后，完成基础设置：

1. 选择 AI 服务来源。
2. 填写 Base URL、API Key、模型名。
3. 测试连接。
4. 选择 TTS 方式：系统 TTS 或外部 TTS 服务。

MVP 至少支持一种 OpenAI-compatible 多模态接口。Ollama、LM Studio、本地服务作为可选连接方式。

### 5.2 创建项目

1. 用户新建项目。
2. 拖入本地视频文件。
3. 软件读取视频元数据，包括时长、分辨率、音轨信息。
4. 软件创建项目缓存目录。

### 5.3 自动分析

软件执行以下任务：

1. 使用 FFprobe 读取音视频信息。
2. 使用 FFmpeg 提取音频。
3. 检测对白或有声区间。
4. 检测静音空隙。
5. 按场景变化和固定间隔抽取关键帧。
6. 对关键帧进行视觉描述和 OCR。
7. 结合对白空隙生成候选口述脚本。

MVP 可以先采用简化策略：

- 每 5-10 秒抽取候选帧。
- 优先在 2 秒以上的静音或低音量空隙插入口述。
- 单条描述控制在 1-2 句话。
- 每条描述绑定起始时间码和预计语音时长。

### 5.4 编辑脚本

用户在时间轴中查看和编辑：

- 起始时间。
- 口述文本。
- 预计朗读时长。
- 对应画面帧。
- 是否启用该条描述。

必须支持的操作：

- 修改文本。
- 删除描述。
- 重新生成单条描述。
- 调整开始时间。
- 试听单条 TTS。
- 试听当前片段。

### 5.5 生成旁白

用户确认脚本后：

1. 软件逐条生成 TTS 音频。
2. 缓存每条旁白音频。
3. 显示生成进度和失败原因。
4. 允许失败条目重试。

MVP 可以先使用系统 TTS，保证无外部 TTS 配置时也能跑通流程。

### 5.6 混音与导出

用户点击导出后：

1. 软件将 TTS 音频按时间码排布。
2. 使用 FFmpeg 与原视频音频混音。
3. 在旁白出现时对原音轨做轻度 ducking。
4. 导出一个带口述旁白的视频文件。

MVP 导出格式：

- MP4 视频。
- 独立 WAV 或 AAC 旁白音轨。
- JSON 脚本文件。

## 6. 功能范围

### 6.1 必须有

- Electron 桌面 App。
- 本地视频导入。
- 内置 FFmpeg 和 FFprobe。
- 项目文件和本地缓存。
- OpenAI-compatible 多模态模型配置。
- 基础抽帧。
- 基础音频静音检测。
- 口述脚本生成。
- 时间轴脚本编辑。
- TTS 试听。
- 混音导出 MP4。
- 日志和任务状态。

### 6.2 应该有

- 导入已有字幕文件：SRT、VTT。
- 重新生成单条描述。
- 简短、标准、详细三档描述风格。
- 连接 Ollama 或 LM Studio。
- 导出独立旁白音轨。
- 失败任务重试。

### 6.3 可以后置

- 模型下载中心。
- 本地 Whisper 集成。
- 本地 VLM 集成。
- 高级混音参数。
- 批量处理。
- 云端项目存储。
- 视障用户审听链接。
- 专业无障碍合规评分。

## 7. 技术架构

推荐架构：

```text
Electron App
  Main Process
    - 文件系统访问
    - 项目管理
    - FFmpeg 调度
    - 任务队列
    - Provider 调用
    - 导出流程

  Renderer
    - 项目页面
    - 设置页面
    - 时间轴编辑器
    - 脚本编辑器
    - 任务状态

  Local Storage
    - SQLite
    - 项目 JSON
    - 抽帧缓存
    - TTS 音频缓存
    - 导出文件
```

### 7.1 模型服务层

抽象统一的 Provider 接口：

```text
describeFrame(image, context) -> description
generateScript(slots, frames, transcript) -> scriptItems
textToSpeech(text, voice) -> audioFile
transcribeAudio(audioFile) -> transcript
```

MVP 至少实现：

- OpenAI-compatible vision provider。
- 系统 TTS provider。

后续再实现：

- Ollama provider。
- LM Studio provider。
- 自定义 HTTP provider。
- 本地 ASR provider。
- 云端 TTS provider。

### 7.2 视频处理层

使用 FFmpeg/FFprobe 完成：

- 读取视频元数据。
- 提取音频。
- 抽取关键帧。
- 检测静音区间。
- 生成旁白音轨。
- 混音导出。

### 7.3 数据结构

脚本条目示例：

```json
{
  "id": "item_001",
  "startMs": 12500,
  "durationMs": 3500,
  "text": "画面切到教室前方，老师指向白板上的流程图。",
  "sourceFrame": "frames/000012500.jpg",
  "enabled": true,
  "status": "ready"
}
```

项目结构示例：

```text
project-name/
  project.json
  source/
    input.mp4
  cache/
    frames/
    audio/
    tts/
    logs/
  exports/
    described-video.mp4
    description-track.wav
    script.json
```

## 8. 描述生成原则

MVP 的脚本生成策略应遵守以下原则：

- 不按固定秒数强制描述。
- 优先描述影响理解的视觉信息。
- 避免覆盖对白和关键音效。
- 语言客观、简洁、准确。
- 不提前剧透。
- 屏幕文字优先识别和朗读。
- 对教程类视频优先描述操作行为。
- 对访谈类视频减少描述频率。

默认策略：

- 每 5-10 秒检查候选画面。
- 优先使用 2 秒以上的静音或低音量空隙。
- 单条描述 1-2 句话。
- 如果没有足够空隙，标记为需要人工处理，而不是强行插入。

## 9. MVP 里程碑

### 里程碑 1：本地视频处理闭环

目标：

- 导入视频。
- 读取元数据。
- 抽帧。
- 检测静音区间。
- 显示任务进度。

验收：

- 一条 5 分钟 MP4 能完成分析。
- 能在项目目录看到抽帧和分析结果。

### 里程碑 2：AI 描述和脚本初稿

目标：

- 配置 OpenAI-compatible 模型。
- 对关键帧生成描述。
- 根据静音区间生成脚本条目。

验收：

- 每条脚本有时间码、文本、对应帧。
- 失败请求有错误提示，可重试。

### 里程碑 3：时间轴编辑和试听

目标：

- 显示脚本列表和视频预览。
- 支持修改、删除、重生成单条描述。
- 支持 TTS 试听。

验收：

- 用户能完整编辑一条 3-10 分钟视频的口述脚本。

### 里程碑 4：混音导出

目标：

- 生成全部 TTS 音频。
- 按时间码混入原视频。
- 导出 MP4。

验收：

- 导出视频能正常播放。
- 旁白时间基本对齐。
- 原视频声音未被完全盖住。

### 里程碑 5：可用性打磨

目标：

- 增加项目保存和恢复。
- 增加日志导出。
- 增加基础设置页。
- 增加错误恢复。

验收：

- 用户关闭软件后重新打开，能继续编辑项目。
- 常见失败能看到明确错误原因。

## 10. 风险和应对

### 10.1 AI 描述质量不稳定

应对：

- 定位为脚本初稿工具。
- 提供人工编辑和局部重生成。
- 提供简短、标准、详细三种风格。

### 10.2 对白密集导致无法插入旁白

应对：

- 标记冲突区间。
- 允许用户手动调整时间。
- 后续支持 extended description，即暂停画面插入口述。

### 10.3 本地模型配置复杂

应对：

- MVP 不强制本地模型。
- 优先支持 OpenAI-compatible 服务。
- 本地模型作为高级连接选项。

### 10.4 视频处理失败

应对：

- 内置 FFmpeg。
- 保存处理日志。
- 明确提示失败阶段。

### 10.5 成本不可控

应对：

- 限制默认抽帧频率。
- 画面变化不明显时不请求模型。
- 缓存每次模型结果。
- 显示预计请求数量。

## 11. 第一版依赖清单

必须内置：

- FFmpeg。
- FFprobe。
- 本地项目数据库。
- 系统 TTS 调用。
- 日志和任务队列。

用户需要配置其一：

- OpenAI-compatible 多模态模型服务。
- 本地 Ollama 或 LM Studio 服务。
- 自定义兼容接口。

可选：

- 外部 TTS 服务。
- 字幕文件。
- 本地 ASR。
- 本地 VLM。

## 12. 推荐首版验收样片

优先选择 3 类样片验证：

1. 3-5 分钟教程视频。
2. 3-5 分钟知识讲解视频。
3. 3-5 分钟宣传片或纪录片片段。

暂不建议用高对白密度电影片段作为首轮验收样片。

## 13. 首版交付定义

MVP 完成时，应能交付：

- 一个可安装的 Electron 桌面 App。
- 一个演示项目。
- 一条原始样片。
- 一条导出的口述影像版 MP4。
- 一份导出的口述脚本 JSON。
- 一份简单使用说明。

首版判断标准不是“是否达到专业制作水准”，而是“创作者是否能用它把口述影像制作流程跑通，并愿意在脚本编辑环节继续使用”。
